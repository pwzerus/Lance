# DEV-053 独立画面审查

审查者：Codex 子代理 head_art_review053；2026-10-30 EDT。只读生产代码及素材，不运行引擎、不修改生产文件。本报告是第二代理的图像/实现审查，不冒称真人试玩或外部专业人士验收。

## 用户截图与 v0.4.12 的结论

用户反馈成立。前次“头到胸 alpha 连通”的检查并不能排除不自然佩戴；连接起来的灰色块和黑色领洞依然像拼接部件。

1. **P1 观感：无须脸的下巴没有真正进入领口。** 用户第一张铁帽截图中，黑色椭圆领口仍明显暴露，脸底像平放在开口上。`eng_armor_0.png` 的不透明黑色领洞本身有深度；它映射到躯干约 y=-91…-79，v052 的 `head_fit.gd::draw_neck(front=true)` 却只到 y=-87，约17单位宽，无法把颈根填到领洞底。下颌、短颈和领前缘需要明确前后遮挡，不应用“灰柱与图像接上了”作为完成条件。
2. **P1 观感：鼻盔壳与可见脸的体积不相称。** `eng_helmet_0` 的名义脸框宽是 .86×64≈55，但代码脸只占32格中的约18格，所以可见脸颊约31，盔顶主体约56。整体头盔缩放与脸框缩放互相耦合，容易一边调整外壳、一边让脸继续显小。应分别控制盔壳、面孔和颈根，先对照鼻盔横向收约10–15%、脸在开口中稍增宽的候选；具体数值以实际图为准，不能把建议值当通过标准。
3. **P2 验证盲点：长胡须遮住了主要问题。** v052 专项 `fighter_for()` 固定 `beard=4`，而用户截图是无须脸。应以默认脸型/无须作为主验收，再检查五种胡须。盖住接缝不等于修复接缝。
4. **保留差异：铁帽帽沿可以比头宽。** 修复重点是帽体贴住头颅、下颌/颈根进入同一领口；不应把铁帽帽沿压到普通鼻盔宽度而丢失形制。此次没有重新考据或把游戏作品当史料。
5. **P2 静态风险：左右转向时的颈根与领洞不在同一空间。** `_draw_impact_torso()` 的胸甲UV固定，领洞偏移不随朝向反转，而 `head_transform.x *= facing` 会使 `neck_x` 反向。底部颈根应锚定躯干空间的领洞，上端再对接头部；不能只调右向人物。此项是代码推断，需候选双向图确认严重程度。

## 建议候选验收

- 主组合：`fr_helmet_0 + eng_armor_0`、`eng_helmet_0 + eng_armor_0`；另看法式低阶甲与普通板甲的领口差异。
- 主脸：默认脸型、无须；补不同脸型、最深肤色和长胡须。
- 主尺度：用户截图对应的正常菜单尺度，同时保留近照供查下巴、领前缘和盔口；不能只在放大的对照板判断。
- 看中心线：颈根落在胸甲开口内，颈宽小于下颌，下颌应有收窄，不能脸底一条直线接黑圈。
- 看遮挡：后领在颈后、前领盖住颈根，左右转向均正确；骑乘俯仰和落马跟随同一局部坐标。
- 看身份：不同头盔仍有明显形制和装饰，鼻盔不再像大罩壳，开放盔不吞脸或切掉眼睛。
