# 当前实现与后续接手说明

## 规则与场景边界

`JoustMatch` 是独立 RefCounted 模型，以 120 Hz 固定步长更新两个骑手的自动前进、速度、耐力、姿态、生命、盾、枪耐久与终止状态。马匹没有互相碰撞的刚体，落马身体才进入 Godot 刚体与关节模拟，因而不存在马匹互撞后停止的路径。

命中使用相对运动扫掠：枪尖角度弧线细分为短弦，每段对移动中的头、身、盾目标求最早接触，并用弧弦偏差补偿。伤害速度包括枪尖挥动与目标移动。每个攻击者每轮最多一次有效命中；先收集双方接触再应用，支持同帧同时败北。当前仍用圆形受击区，是游戏抽象。

速度单位为像素/游戏秒；HP、冲击指数、稳定性和断裂概率均为平衡参数，不对应历史实测牛顿、人体致死能量或真实事故统计。姿态使挂点与盾倾角变化，不对关节、骨骼或材料做完整生物力学仿真。

## 时钟

命中顿帧 50 ms、慢动作恢复时刻与结算展示使用真实时钟，避免 Engine.time_scale 导致永远无法解除。慢动作窗口内不消耗 0.2 游戏秒的过阵冲刺。暂停冻结 world 及布偶；HUD 保持可交互。恢复、重开、退出都恢复 time_scale 与鼠标可见状态；暂停期间的结算展示时间不前进。

## 输入

鼠标事件经 Godot 视口拉伸/DPI 转换后记录位置；物理步读取该位置。持续按键和按钮通过 Input 状态读取。输入测试需要按真实顺序刷新事件队列，不能把不改变系统指针的注入事件与 OS 光标轮询混为一谈。

触控按 ID 分配姿态、瞄准和额外加速，跨区保留初始角色，抬起、取消、暂停和失焦清理。这里只通过合成触控事件验证了状态逻辑，未在手机上测试触感、触摸面积与系统手势。

## 进度

目录为 34 项，五个解锁窗口。玩家装备合并为战斗参数，NPC 使用独立年代配装。AI 反应与误差有三档，当前需要真人进一步调平衡。

完成一局立即奖励且按 session_id 去重。玩家死亡不删除收藏。存档先写临时文件并 flush，保留上一个有效主档，再替换主档；读取损坏主档时回退备份，类型异常字段回退默认。购买和装备的磁盘写入失败会回滚对应改动。比赛奖励保存失败时仍保留内存进度并报告错误，当前未实现跨进程交易日志。

## 范围明确的后续工作

先收集实际试玩对瞄准、前后倾、冲锋节奏和 AI 的反馈，再做更准确的马匹步态、落马关节与专属四肢防具。随后按具体文物扩展地区主题、马衣马铠、盔饰和纹章联动。继续使用来源编号和描绘窗口，不把更多装备简单变成数值越来越高的同一张图。
