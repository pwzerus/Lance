# PERF-088 入场、重开与动作复验

基线3b6b04d / v0.4.41-r6，2026-11-12。仅原三份历史差异保留；无新Claude代码。默认后台、隔离QA、全部资源保护保持；本机真实GPU不等于OS操作或真人手感。

## 定位与实现
旧包baseline01首次重装入场57.800ms（同步16.69ms），后四次31.36/31.82/25.75/25.59ms。探针profile01显示HUD同步构建约5–11ms；首次两骑手绘制/上传与旧页面释放也挤在同帧。原087已经预热贴图，继续预热相同贴图不能消除这些创建工作。

Main启用Battle的分帧准备：先建静态场地，再各自完整绘制两名骑手，最后HUD；保留所有节点/材质/纹理/网格和动作。准备背景遮住半成品，约四帧后才启动完整倒计时。模型不推进、输入不改动半成品。直接Battle规则夹具仍同步初始化，生产Main才启用分帧；性能结论必须量真实Main而非这些夹具。

## 发现与修复（保留失败证据）
- staged01峰值降到约28ms，但Battle阴影_draw仍假定两名骑手已经存在，产生数组越界；不能算通过。已加入presentation_ready绘图门槛，等待复验。
- 静态复核发现WindowActivity最小化会在HUD/音频尚未创建时请求暂停；增加延后暂停记忆，恢复后建完界面仍需明确继续，音频存在时先暂停。lifecycle01验证五个阶段取消、隐藏停建和12次重开功能断言通过，但同样有上述_draw错误，必须复跑零错误版本。
- 所有原始失败日志保留logs/perf088，未把通过断言数用作质量结论。

生命周期02已无绘图越界，但取消四个尚未完成的准备过程后，退出报告四个Shape2D资源遗留。诊断为跨await保留局部RectangleShape2D的构建栈；把静态场地构建提取为同步方法，让局部资源在让帧前退出作用域，等待verbose生命周期03复验。正常已完成比赛不复现此取消专属路径；失败仍保留。

生命周期03进一步证实Shape2D清理已修，但取消后仍留四个GDScriptFunctionState，均指向嵌套_preparation_frame。最终改为明确的四段逐帧状态，无await挂起栈；准备暂停/取消直接随节点生命周期结束，避免用超时等待掩盖泄漏。此为实现纠正，保持相同完整资源和准备语义。

生命周期04实际GPU/verbose通过：五个取消阶段、隐藏三秒停建/恢复明确继续、十二次重开，旧Battle全部weakref释放、音频总线固定5、无奖励增长，退出0且日志无ERROR/WARNING、无孤立FunctionState或Shape2D。最终明确状态实现不再使用await。准备独立0.4.42进行包内性能、动作和接触复验，尚未切试玩入口。
