# 骑枪游戏对照研究与攻防设计建议

记录日期：2026-10-24（America/New_York）。对应用户反馈：持续瞄头成为优势策略，前后倾缺少可感知的博弈价值。使用项目 joust-game-feel 工作流整理，本轮不修改已发布 v0.2 的代码或规则。

研究范围为官方商店说明、开发者页面、官方更新和宣传入口。没有安装、购买或亲自试玩这些作品，也没有逐帧观看完整视频。商店声称的功能不等于已验证质量；早期更新不等于当前版本精确公式。下面明确区分来源事实与设计推断。

## 最直接的对照

### 1. Speedy Spears：2D、攻击角度、盾角和马速

来源：[开发者 Steam 商店](https://store.steampowered.com/app/1796040/Speedy_Spears/)。检索时显示 Coming soon，并提供 Demo 入口；不能称为已经正式发行、经过市场验证的成功作品。

官方明确说明玩家需要损坏对方护甲，至少经过两次交锋；每人分别选择攻击角度、盾牌防御角度和马速（trot/gallop）。资料未说明这些角度是完全连续控制还是阶段选择，也未公开反应窗口或胜率。

对本项目的启发：固定跑道没有自由走位时，主动盾角可以成为第二个操作维度。速度不能只提高数值，需要改变出手与防守的难度或时机。多次交锋可以保留观察与调整机会，但“至少两次”只适合作为竞技场方案候选，不能照搬成实战永不一击致命。

### 2. Joustaposition：枪盾分控，失衡后再完成落马

来源：[开发者 itch.io 页面](https://joustaposition.itch.io/joustaposition)。该页标为 Released，但它是小型独立项目，不作为商业成功证据。

官方玩法说明中，右摇杆控制枪，十字键触发盾的方向动作；攻击对方盾牌会降低稳定状态，稳定耗尽进入脆弱状态，之后一次关键命中可落马。移动沿预设路线进行。

对本项目的启发：盾牌格挡不必只有“完全无事”和“扣血”两种结果，可以保护身体同时承受可恢复的失衡压力，让攻击盾牌也能为后续交锋创造机会。我们的当前平衡值主要是累计损失，还缺少明确可读的失衡阶段与恢复决策，不能因为已有一个数值就称为实现了同样机制。

开发者在页面评论中承认键盘操作是后加的、较笨拙。对应教训：本项目应先按 Windows 鼠标键盘设计枪盾操作，不能直接照搬手柄四方向要求。把枪、盾、姿态、催马都变成持续独立输入也可能超出单人操作负担，需先验证。

### 3. Joust Legend：安全攻击与精确高风险攻击

来源：[Rebellion 的 App Store 产品说明](https://apps.apple.com/us/app/joust-legend/id680539008)。检索时有产品页面，但不承诺用户所在区服、设备兼容性或购买后的服务可用性。

开发者介绍赛前技能增益选择，以及安全打法和精确攻击之间的决策；介绍真实骑枪动作采集、马与骑手的动作捕捉、慢动作重放和装备组合。页面未给出确切攻击部位倍率、盾角系统或输入锁定机制。

对本项目的启发：风险应在攻击之前就能被理解。稳定的大目标攻击与精细高收益攻击可以共存；精确高收益攻击不能同时拥有最容易瞄准、最快调整、最好防守的全部优点。动作与回放可用于解释命中，但不能取代攻防规则。这里不把其“真实”宣传直接当作中世纪史料。

### 4. Mount & Blade II: Bannerlord：冲击效果依赖相对速度

来源：[TaleWorlds 官方 e1.5.1 更新](https://www.taleworlds.com/en/News/384)、[官方 v1.3.0 更新](https://www.taleworlds.com/en/News/581)。前者是2020年的历史调校记录，不代表当前精确公式。

早期官方更新明确将夹枪和架矛的主要效果限制在较高相对速度下。后来的官方动画更新提到持枪姿势与被动盾姿之间的关系：握法改变可能略微影响防护。

对本项目的启发：有效冲击应来自骑手、武器和目标的相对运动及稳定接触，而非枪尖一碰头就独立触发固定胜利。盾是有方向和覆盖范围的实体，而不是通用防御百分比。自由战场中还有接近路线和转向；我们限制了这些选择，就需要在盾、姿态、时机等方面补足，而不能只复制其高伤害。

### 5. Lance A Lot Classic：一击胜负也能成立，但前提不同

来源：[Brimstone 官方新闻资料](https://brimstone.games/lance-a-lot-classic-press-kit)。开发者说明枪尖一击即可击落对手，场景是骑士乘火箭在空中竞技，并有可受物理影响的环境和不同规则。

对本项目的启发（推断）：一击胜负本身不等于没有博弈。如果到达有效接触位置的过程有足够的操控与对抗，短暂结果可以形成紧张感。但是本项目是相向固定跑道，不能靠照搬一击规则获得同样的过程。用户要求实战允许死亡，不必为了公平强制人人吃多枪；需要先让防住、诱骗和打空成为可信的可能。

### 6. Last Knight: Rogue Rider Edition：命中演出和声音应配合

来源：[开发者 Steam 商店](https://store.steampowered.com/app/262210/Last_Knight_Rogue_Rider_Edition/)、[开发者 Update #4](https://steamcommunity.com/games/262210/announcements/detail/1262444873044450721)。它是夸张的骑枪动作/跑酷参考，并非等价的传统双人比武。

开发者更新记录慢动作同时降低声音速度，并提供关闭第三人称镜头起伏的选项。

对本项目的启发：冲锋声、接触声和慢动作不能互不相关。接触局部音画同步比持续震动更能解释力量；镜头表现需要舒适性选项。该作品不能证明我们所提的盾位、假动作或压枪窗口已经有效。

## 补充演出参考：Rival Knights

[Gameloft 官方发布预告入口](https://www.youtube.com/watch?v=X-JO9mMnyqM)、[原始提案设计者作品页](https://www.colinegattolin.com/rival-knights)。设计者确认最初循环为定制、战斗、升级；官方预告确认该骑枪作品及移动端定位。存在关于分段催马、瞄准与落马的二手说明，但本轮没有一手操作手册或实机验证，不以二手摘要断言其精确防守机制。将它列为进一步观看冲锋构图、阶段提示与落马演出的入口，不宣称它已经解决实时双人博弈。

## 针对 GALUMU 的判断

### 当前问题的结构

玩家主要控制攻击角；双方沿固定路线接近，盾角不是独立主动决策，姿态变化又能被持续追踪枪尖抵消。伤害阈值调整可以消除某个秒杀分支，但不能单独增加决策深度。现有自动断言只能验证输入、伤害和姿态是否按设定运行，不能证明“始终瞄头”已被可靠反制。

### 优先验证的三个改动（研究建议，尚未实现）

1. **主动盾位。** 先试高/低两档，切换带短动作时间和明确剪影。高盾保护头胸、低盾保护腰腹；覆盖依真实几何实现，不能仅在命中后掷骰认定格挡。盾可承受冲击和失衡，不能永久消除所有风险。
2. **压稳骑枪与修正代价。** 鼠标仍能控制武器，但强力接触需要先压稳。大幅改向会降低稳定，并需要时间重新找回支撑；小幅修正保留。不要一进入距离阈值就突然锁死鼠标。假动作应来自可见的准备和切换成本，不必额外创造一个“假动作键”。这是本项目的假设，不是上述游戏统一采用的机制。
3. **姿态改变真实攻防。** 后仰可避开已承诺的高枪，但削弱自己的稳定攻击并暴露腰腹；前倾提供支撑或较好盾覆盖，却更难临时后撤。动作应在接触前足够早可读，不能等命中后才宣告姿态选择有效。

### 模式边界

竞技场优先比较有效命中、稳定和落马，可尝试累积压力，不取消每轮新枪及非致死保证。实战保留致命可能；高质量命中暴露要害可以决定胜负，但应与护甲、有效速度、攻击支撑和对手防护相联系。两模式的平衡和历史解释仍要分开，不将这些游戏数值称为历史损伤统计。

### 验证方式

先保持同等装备，比较“持续追头”“根据盾位变招”“高低交替”“只后仰”“只冲刺”等策略，并交换左右出生位置。用反应延迟与瞄准误差合理的对手，不能让AI看玩家当前输入立即完美反制。

需要能观察到：高盾确实削弱追头的收益；低枪能针对过度后仰；提前露枪有被识破的代价；临时变招可能成功也可能因不稳失败；速度有收益也有控制成本。记录命中区、格挡、打空、落马、死亡和双方动作时间，再进行真人试玩。不要在未试验前承诺某套组合必然产生深度或精确胜率。
