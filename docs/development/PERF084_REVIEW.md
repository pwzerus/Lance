# PERF-084：绘制错误、切换卡顿与重甲帧率

日期：2026-11-10（America/New_York）。负责人Codex。接手实际HEAD `dd72c20b2774b481bc068386028558262f62862a`，codex/v0.4，与origin一致；没有新的Claude游戏改动。上一轮已有V051两份密文文档差异、rules_v045_results.json及历史未跟踪材料，保留且不暂存。

## 结论与修改原因

1. **可重复的枪杆绘制错误已修复。** 大量接触/落马自动运行未复现后，50万枪形状扫描找到一个近共线轮廓；交给原生产LanceArt.draw时稳定触发 `Invalid polygon data, triangulation failed`，调用点lance_art.gd旧第61行。枪杆填充消失、轮廓仍在。不是缺少贴图，不靠跳绘掩盖。枪杆本来就是上下边缘构成的带状网格，现直接提交相邻截面的固定三角连接，保留全部顶点、弯曲、粗细、颜色、描边及碎片效果，避免每帧重新猜三角连接。精确同顶点修复前后GPU图像和日志留存。
2. **切场景重复初始化和屏外图片加载。** 原代码每次营地/军械库预览及比赛重新计算马体静止网格权重；现仅共享3种静止模板，动画顶点与GPU网格仍各实例独立。军械库盔甲卡片按可见区域加载，按帧分摊，离开页面后未开始任务自然随节点释放。单张图片加载可能超过2ms预算，预算不是硬实时承诺。
3. **每帧重复几何工作。** 马体刚性点用原生数组变换，所有受影响顶点继续原完整计算；头盔/胸甲固定适配数据最多64项，盾面局部纹章/木板几何最多48项。头颈/盾移动和碰撞、120Hz物理、音频、动作、美术完全保留。

原生机制核对：[Godot 4.5.1 renderer_canvas_cull.cpp](https://raw.githubusercontent.com/godotengine/godot/4.5.1-stable/servers/rendering/renderer_canvas_cull.cpp) 与 [canvas_item.cpp](https://raw.githubusercontent.com/godotengine/godot/4.5.1-stable/scene/main/canvas_item.cpp)。polygon路径调用Geometry2D三角剖分；triangle_array可直接使用已知带状连接。当前精确复现证明同一生产路径/同类原生报错可以被触发并消除，**没有恢复上轮报错那一帧，不能证明所有历史绘图告警都只有这一原因**。
