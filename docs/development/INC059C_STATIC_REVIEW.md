# INC-059C：静态内存调查与重复计算修正

2026-11-03，基线01ec9fb，Codex。遵循用户“暂时不要运行游戏”：本轮没有启动Godot、游戏、导出、桌面自动化，也未修改玩家存档。40GB事故根因仍开放P0；下述性能修正不是泄漏归因。

## 已证实并修改的性能问题

1. `rider_view.gd::_horse_leg_pose`原先无条件执行完整`Gait.leg`，随后在已有4条腿缓存时丢弃结果。现在先返回已有结果，仅首次绘制无缓存时求解。常规两匹马每次绘制合计省去8次完整IK求解；若实际60帧则约480次/秒，是调用数推导而非FPS实测。`Gait.leg`是无副作用的静态计算，缓存内容与原返回结果相同。
2. `battle.gd::_on_hoof_contact`同样先计算再覆盖，改为有缓存用缓存、无缓存才求解。马蹄位置、声响参数和步态不变。
3. `horse_skin.gd`每匹马3个网格共3427个顶点。每次更新重复读取不变的颈/尾姿态和计算固定枢轴，改为每个网格更新读一次；尾部`source.y`对应的smoothstep系数在初始化计算，以Float64保存以免新增float32截断。增加约27KB固定系数存储/马，不是零内存代价，换取减少重复计算。
4. 后腿裁剪多边形原来每个三角形都重新构造PackedVector2Array；每个后腿网格初始化1152次构造改为1次（其他网格现在也各构造1次，不影响拓扑）。骨骼变换的同向量3次normalize改为1次。
5. 骑手已持有当前头盔纹理，却每帧再次调用装备纹理LRU查询并删插字典，改用已持有的`head_texture`。换装仍由原有art_key更新路径触发，未新增全局无限缓存。

上述改动保持网格密度、坐标、曲线、碰撞、接触节拍、枪盾速度和画面层次。尚未做引擎解析或渲染回归，不能称为已验证新版本。
