# PERF-088 入场、重开与动作复验

基线3b6b04d / v0.4.41-r6，2026-11-12。仅原三份历史差异保留；无新Claude代码。默认后台、隔离QA、全部资源保护保持；本机真实GPU不等于OS操作或真人手感。

## 定位与实现
旧包baseline01首次重装入场57.800ms（同步16.69ms），后四次31.36/31.82/25.75/25.59ms。探针profile01显示HUD同步构建约5–11ms；首次两骑手绘制/上传与旧页面释放也挤在同帧。原087已经预热贴图，继续预热相同贴图不能消除这些创建工作。

Main启用Battle的分帧准备：先建静态场地，再各自完整绘制两名骑手，最后HUD；保留所有节点/材质/纹理/网格和动作。准备背景遮住半成品，约四帧后才启动完整倒计时。模型不推进、输入不改动半成品。直接Battle规则夹具仍同步初始化，生产Main才启用分帧；性能结论必须量真实Main而非这些夹具。

## 发现与修复（保留失败证据）
- staged01峰值降到约28ms，但Battle阴影_draw仍假定两名骑手已经存在，产生数组越界；不能算通过。已加入presentation_ready绘图门槛，等待复验。
- 静态复核发现WindowActivity最小化会在HUD/音频尚未创建时请求暂停；增加延后暂停记忆，恢复后建完界面仍需明确继续，音频存在时先暂停。lifecycle01验证五个阶段取消、隐藏停建和12次重开功能断言通过，但同样有上述_draw错误，必须复跑零错误版本。
- 所有原始失败日志保留logs/perf088，未把通过断言数用作质量结论。

生命周期02已无绘图越界，但取消四个尚未完成的准备过程后，退出报告四个Shape2D资源遗留。诊断为跨await保留局部RectangleShape2D的构建栈；把静态场地构建提取为同步方法，让局部资源在让帧前退出作用域，等待verbose生命周期03复验。正常已完成比赛不复现此取消专属路径；失败仍保留。

生命周期03进一步证实Shape2D清理已修，但取消后仍留四个GDScriptFunctionState，均指向嵌套_preparation_frame。最终改为明确的四段逐帧状态，无await挂起栈；准备暂停/取消直接随节点生命周期结束，避免用超时等待掩盖泄漏。此为实现纠正，保持相同完整资源和准备语义。

生命周期04实际GPU/verbose通过：五个取消阶段、隐藏三秒停建/恢复明确继续、十二次重开，旧Battle全部weakref释放、音频总线固定5、无奖励增长，退出0且日志无ERROR/WARNING、无孤立FunctionState或Shape2D。最终明确状态实现不再使用await。准备独立0.4.42进行包内性能、动作和接触复验，尚未切试玩入口。

发布包同驱动对照：old-package01首次62.172ms、后续最高41.316ms；首个.42候选首次仍42.392ms（在HUD阶段），后续最高20.106ms，总准备约84–101ms。所以尚不把首次卡顿记为完成：继续把完整HUD上/下两组分帧创建，保留同样控件与字体，同时补首帧阴影、入场时Esc/失焦记忆。lifecycle05确认暂停路径，无错误/遗留；下一候选为.42-r2，旧.42不覆盖。

## 内存等待期间的静态补查
r2导出被原启动预算拒绝，InspectOnly实际可用1213MiB；没有把CIM访问被拒后的空值当成0MiB。未关闭用户应用、未降低保护，未产生r2运行包，继续静态工作。

又发现Rider.set_process(false)放在add_child之前会被Godot READY的自动启用覆盖，准备阶段两骑手仍会反复计算/重绘。已移到add_child之后，并补准备期间is_processing=false及完整倒计时不推进断言。依据是[Godot4.5.1 Node::_notification READY源码](https://github.com/godotengine/godot/blob/4.5.1-stable/scene/main/node.cpp#L238-L245)显式set_process(true)，属于确定的初始化顺序问题，不靠削减动画解决。结束准备时仍统一恢复连续动画。尚待新运行证据确认收益。


## 恢复内存后的实际包复验（c1e5f0a / 0.4.42-r2）
用户释放内存后InspectOnly为2705MiB，原保护允许export03；没有调低预算。独立runtime和原生启动器完整构建，运行源码c1e5f0acd7914cf30ca6b76e6a8e9daa75016b65。

- r2-lifecycle01：六个准备阶段取消、完整倒计时冻结、骑手初始化后不提前process、准备期间Esc/失焦、最小化三秒与显式恢复、十二次重开全部通过。退出0，无意外引擎错误/警告。
- r2-transition01：同一外部脚本、重甲、菜单实际预热两秒、实际发布包。首次最长25.458ms（旧62.172ms），后四次最长19.124/17.894/17.663/17.555ms（旧最高41.316ms）；完整准备约100.5–101.0ms。不是OS重启后的冷磁盘或每台电脑保证。
- r2-war01：正常Main/Battle、自动操控与结算按钮引擎输入，180.006秒三场重甲实战，平均59.711FPS，p99 21.683ms；冲锋/接触最大26.36/27.972ms。全程最高48.32ms、8帧>33.33ms，集中turn；仍非锁60。进程组私有内存峰657.5MiB。
- r2-turn-probe01：为定位少量长帧又跑120秒，平均58.028FPS，最大43.502ms；本轮>30ms主要在终局受击/落马及一帧冲锋，没有复现固定turn热点。探针含逐帧诊断开销，不能将其直接当更快或更慢的生产A/B。没有证据支持靠改回合规则修帧率，后续PERF-089需剖析这些尾部帧；不能宣称所有尖峰消失。
- r2-motion01：四马皮、双向、轻重装，分别12游戏秒，真实120Hz模型/60Hz视觉，取样15fps共720图；只写盘、不无界保存Image。催马峰速486–496，松手末速213–217，头挂点120Hz最大步长1.63–1.90世界像素；高速连续三秒马背/骑手同为12–13次反向，约7.2像素峰峰值，未见原先短频重复反转。取样图检查近远腿、颈部接缝及前后倾；不把这些数字当真人自然度认可。
- r2-feedback02：真实120Hz扫掠之后实际GPU头/胸与双向盾心演出；重击接触近景约+28.4%，屏幕逻辑震动峰24–30px，阅读慢动作约0.276–0.285真实秒、时间倍率0.28，结束恢复1；慢动作关闭无阅读段。枪盾位置来自共享挂点，连续移动断言保留，暂停/恢复不跳相位；实际截图头胸回退及盾压缩可辨、未侵入HUD。没有真人试听或OS输入结论。
- r2-audio01：包内头盔/胸甲/盾材质选择、PCM峰值、组合音量预算、有限声音池与暂停释放检查通过。Dummy音频，不宣称实际扬声器或主观听感通过。
- r2-zip-inventory01：ZIP解压到中文/空格目录，经原生保护启动，48头胸甲/72枪条目、四马皮/15马衣与许可核对通过；打包未混入开发测试。
