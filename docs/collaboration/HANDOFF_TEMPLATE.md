# 双向交接模板与提交约定

Codex→Claude、Claude→Codex 或人工接手均使用本模板。复制到 `docs/collaboration/handoffs/` 下的新文件；以下空项由实际负责人填写，不能把模板内容当成已验证事实。

## 版本、分支和 commit

仓库：<https://github.com/pwzerus/Lance>，远程名 `origin`。当前版本分支 `codex/v0.4`。每个版本一个分支，修复和同一／相近功能在现有版本分支内提交；大的结构性改动形成下一版本时才开新版本分支，例如 `codex/v0.5`。不要按开发者姓名各开一条长期版本分支，也不要因每个小功能新开分支。下一版本名称应与实际阶段计划一致，不能把例子视为已经创建。

开始工作先读实际 `git status`、`git branch --show-current`、`git log -1`，再查看远程更新与文件认领。工作区有别人的未提交改动时不能直接覆盖、reset或强行切换。切换版本或合入提交前先明确基线与归属；遇到历史分叉用普通审查／合并处理，不 force push。

每个 commit 表达一个能解释的变化，示例：`fix: preserve spur input through countdown`、`feat: add readable shield transition`、`docs: record v0.4 validation scope`。提交说明写清为什么改、可见行为变化、已运行验证／未验证项。只暂存自己的具体文件；不依赖 `git add .` 把对方改动或QA输出一起提交。

里程碑完成后推送当前版本分支，让双方看到相同提交。接收者核对 SHA、实际差异和相关证据后回填下方接收回执。不要把未推送的本地改动说成已在 GitHub 可见。`builds/`、`tools/` 和 `.godot/` 被忽略，GitHub 分支不自动包含 Windows 可执行包；没有另行发布时不声称 Release 已上传。
