## 发现

### P2：历史年代覆盖会提高12件装备的实际购买门槛

### P2：新粗枪断裂后，碎片会立即变细，涂装节奏也不连续

静态几何可证，尚未做引擎连续帧复现。`game/scripts/visual/lance_art.gd:18–29`按类型、品质和沿枪位置计算半径；例如reach255、quality5的stout最大半径约7.14，木体全宽约14.28，加描边约16。`game/scripts/visual/lance_shard.gd:20–27`仍固定8像素外轮廓、5.5像素木体和25像素彩条间距，未采用原枪的半径、锥度和涂装起始位置。`impact_fx.gd:47–74`虽然传入了equipment，但没有传原断段沿枪坐标；新碎片的类型只被枪头绘制使用。

结果是高档粗枪可在断裂首帧约缩为一半外观厚度。原整枪的条纹间距为23或30、方向还随地区变，而碎片重新从自身局部坐标起画25像素斜条。用户特别关心断枪演出，此差异在近身放缓时更值得处理。

建议保留既有RigidBody2D数量、速度和碰撞层，仅给碎片传`source_start`、`full_reach`，使其皮肤沿用`Lance.radius()`与相同彩条相位；或至少由类型/品质计算断段粗细。用一支高档stout及一支light，左右各一次，记录断前/断后首帧/飞散约0.1秒，核实轮廓连续；不需要为这个表现修复改规则伤害。

## 已核对、未发现本轮实质故障的路径

- **图ID与收藏兼容**：研究覆盖不删除旧ID；`find()`返回现有字典后仅局部更新，已有装备数值、价格、品质字段保留。48条研究记录的stats当前只有`armor_material`或`helmet_material`，未夹带数值覆盖。`sanitize()`仍保留目录中已购ID，`equip()`只要求已拥有且写盘成功。旧版`armor_e2`没有被硬套晚期原物，保留旧图是明确设计取舍。
- **材质音效**：新材质分字段进入最终stats，头部读`helmet_material`、躯干/腹部读`armor_material`；mail、brigandine、plate、padded各走已有contact bank。没有为本轮另加第四阶段运动甲片音。旧别名的当前材质与旧tier回退基本相符；该判断不代替实际听音。
- **枪尖锚点**：`Lance.surface()`在distance=length时弯曲项为`sin(PI)`，中心端点等于hand+axis×length；broken分支完全无弯曲。`rider_view.gd:281–285`恢复同一facing变换后绘枪，Model的hand/tip锚点与长度没被改。`draw_tip()`所有顶点沿轴偏移≤0，枪头几何中心端点不往前偷偷延伸。描边约0.8像素与竞技场两侧冠齿宽度是显示边缘，不把它们称额外实体碰撞。
- **枪盾限速与规则**：本轮所审diff没有改`set_controls()`、命中扫掠、伤害、死亡/KO、时间演出或盾控制；装饰不写回Model。腿纹仅由地区选择绘制路径，未增加腿防护字段或碰撞目标。断枪碎片沿用原两个刚体和分跑道碰撞遮罩。
- **导出可达性**：新manifest及历史数据位于`data/*.json`，现导出include_filter覆盖该目录；PNG位于项目assets。外部研究照片不应被加入运行manifest。发布版本字符串和路径仍由root统一更新，本次未把开发中旧版本号列成已发布错误。
- **历史UI结构**：制造地、用途、来源和改编说明放进固定高度ScrollContainer；购买按钮与来源按钮留在滚动区外。描述文案有明确长度控制，避免把整条历史注释压在头像旁。没有静态证据证明目前文字一定截断，但仍需实际渲染检查。

## QA边界与最小补验建议

这些是当前测试覆盖缺口，不声称已经复现生产问题：

1. `test_equipment_v051.gd:145`用`tier%2`给每件只选一个方向，`143`固定arena，且没有抬盾或前后倾。区域六件合照能看整体，不能证明**每件**左右两面、开放脸口和肩颈重叠都正确。至少补所有开放盔双向脸口，以及最宽/最长胸甲在护头、前倾、后仰时的双向真实骑手图。不要因为同一张合照里有左右两个人，就写成每件都验过双向。
2. 当前武器展示和规则模拟没有实际渲染新三类枪的全长、断柄及飞散首帧。最小补上两模式、左右、最高档stout与最长杆的近身连续帧，同时把规则tip投影坐标记入日志；数学同端点不等于玩家一定看清命中位置。
3. `asset_checks()`看manifest的散列字符串是否不同，没有把运行源文件重新散列。它能抓重复声明，不能单独证明文件内容与声明一致，更不能证明形制不只是换色。本轮DE12另有实际SHA检查与目视结构审查；其余地区需各自实证。
4. 材质检查`57–58`仅检查结果属于合法家族，若意外把mail映射成plate仍可能通过。建议比较当前item显式材质的**预期家族**，再加一件legacy alias以检查回退；不用大量重复断言替代听感。
5. 商店测试`183–194`只选法兰西最高档三种槽位，且只验按钮在面板内、滚动区高度合法，没有验长文本实际底部、滚动后是否能读完或来源按钮可点击。选最长日期/最长制造地/最长注释各一条，滚至底部，并在最小960×540和一个非16:9窗口确认逻辑视口与可点击区域。UI固定逻辑布局不必重复所有48件文字。
6. 已有存档专项测了自动/手动重载、新旧ID兼容；本轮新图与文本不应触碰正式档。购买失败回滚、暂停、30/60/120控制限速等沿用已有专项回归，由root按本轮实际改动选择复验；不能把本脚本的规则比较扩大描述为完整输入或真人试玩。

以上发现已发root，源码由root认领修复与串行引擎复验。本报告没有把测试断言数、图片数量或独立散列数量当作历史准确性或游戏好玩的证明。
