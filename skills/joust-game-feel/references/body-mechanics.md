# 骑乘人体动作专项检查

用于用户指出骑手僵硬、肢体错位、像木偶或动作不流畅时。此表是本项目审查方法，不是行业认证；下载的技能也不等于专业人士已经验收。

## 先看力从哪里来

- 抬枪：已缓动的实际枪线带动握点、前臂和肘，肩口保持连接。不要让枪杆绕完全不动的拳头转一大圈，也不要让视觉握点脱离扫掠碰撞锚点。改共享锚点后要重新检查左右命中与关卡难度，不能当纯美术修复。
- 抬盾：手柄由左手带动，肩肘有可达范围；三分之四视角需要区分远近投影，不能把两个右手镜像当成左右手。远侧缩短是深度投影，不是落马时可以重新缩放骨长。
- 俯仰与骑乘：骨盆由马鞍支撑，腿跨在马两侧；启动/制动的躯干跟随与头部稳定相互配合。高频随机颠簸、多个无关正弦并不等于更真实。
- 失衡：明确离鞍、回落与坐稳的顺序。特别检查半波/钳位曲线的接点；位置连续但速度突然断开，仍会像被硬拽。
- 受击/落马：从实际接触姿态开始，让躯干、头、持械手和腿按力的方向先后响应；接地后保留惯性与阻尼，不能直接切换成另一个躺姿，也不能用隐藏、瞬移或缩骨头来消穿模。

## 怎么观察

先用正常时间看动作意图与轮廓，再用慢速与逐帧定位接缝；左右朝向、中立与极端姿势、起步/换速/松开、轻重装备各选有意义的代表。单张好看的截图不能证明过渡流畅。

数值证据检查握点一致、骨长/关节限制、接触瞬间连续、30/60/120Hz收敛和慢动作时钟；画面证据看肩肘是否可读、身体是否有支撑、视觉接地与计算包络是否相符。画面正确与数值正确不能互相替代。文字疑似缺字时查看原始分辨率和实际字符串，避免把聊天图片缩小预览当成字体故障。

保留原始失败图/日志。用同场景、相同装备/朝向/输入的前后对照说明修复，最后通过真实场景和发布包检查，不只验证摆拍图集。没有真人试玩时明确剩余手感验收。

## 来源与适用范围

- [Wayne Gilbert / Animation Mentor：Body mechanics](https://www.animationmentor.com/blog/animation-tips-tricks-what-makes-or-breaks-a-good-body-mechanics-shot/)：关注力的来源和身体各部分的先后关系。此处将方法应用于骑乘，具体姿态参数是项目设计。
- [Nathaniel Seymour / Animation Mentor：Overlap and follow-through](https://www.animationmentor.com/blog/tutorial-animate-overlap-and-follow-through/)：主动作之后的跟随与收势需要适度，过多会漂浮、过少会僵硬。
- [Anthony Wong / Animation Mentor：Appealing poses](https://www.animationmentor.com/blog/tutorial-building-appealing-character-poses-for-animation/)：结合重心、轮廓和动作线评审，避免复杂肢体互相缠在一起。不是把其3D工具教程直接搬进Godot。

四个下载技能的固定版本/许可证见 `skills/external/SOURCES.json`；引擎仍为Godot4.5.1，外部新版本代码不能未经核对直接复制。
